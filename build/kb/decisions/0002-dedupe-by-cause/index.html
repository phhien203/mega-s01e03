0002 · Merge by supported cause, not subject

owner phhien203 and Pi accepted reviewed 2026-10-28 · 0 days ago

Supersedes: 0001 · Duplicates share a subject line. That accepted decision remains unchanged as the historical record.

Matching subjects merged two different date causes into #4471. The old choice saved reading time but hid a separate fix and kept misrouting new reports. The desk will spend more time checking evidence rather than merging on subject alone.

Read the body and check the tenant’s actual locale, booking form and channel. Use the supplied cause logic for this incident. Merge only when the evidence supports the same cause; a subject match is neither necessary nor sufficient. Browser locale and intake tags are hints, not the tenant configuration. Unknown tenants and contradictory symptoms need investigation, not an automatic merge. Deduplicate by report ID before counting.

Apply this rule to incoming reports immediately using the current triage runbook. Keep parser and form-hint tickets separate while fixes are pending. A shared symptom does not justify a shared fix. The report export is a snapshot; recheck the live queue before resolving the incident.
